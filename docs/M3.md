## 隔离开发环境

源码位于 `minecraft/`；JDK、Gradle ZIP/解压目录和 Gradle 用户缓存位于 `.local/minecraft-dev/`，均忽略提交。
Minecraft 构建输出与项目 Gradle 缓存亦忽略提交。下载的 JDK、Gradle ZIP 已按锁定 SHA-256 校验。
构建脚本只临时设置本进程的 JAVA_HOME、GRADLE_USER_HOME，并在结束后恢复；不修改系统 PATH 或现有 JDK 17。
不复制游戏 JAR、原版资源或第三方依赖到源码仓库或 Mod 分发包。

```powershell
# 下载必须先获得用户确认；已有归档会重新校验，不覆盖未知工具目录。
pwsh -File tools/PrepareMinecraftDev.ps1 -ConfirmDownload
# Gradle 构建可能下载依赖，因此也要求显式确认。
pwsh -File tools/BuildMinecraft.ps1 -ConfirmDependencyDownload
```

最初最小入口没有 Java 测试。当前新增独立 `bridgeCheck` 自动检查任务，由 `check`/`build` 执行；不使用 JUnit，因此标准 test 允许没有 JUnit 可发现的用例。
早期构建有 Gradle 弃用提示，已修正本项目资源任务在执行期访问 Project 的用法；不据此承诺兼容 Gradle 10。

## 石头权威原型

- `BridgeProtocol.java`：四字节大端长度前缀、UTF-8 JSON，保持 C# 大写字段名。严格验证帧长度、身份、版本、数值与必要字段；队列和快照预算有界。
- `MinecraftBridgeServer.java`：只监听 `127.0.0.1`；默认端口 25575。网络线程不访问引擎，入站请求队列 64、出站队列 128。请求交给 END_SERVER_TICK，状态变化由独立网络写线程发送，不阻塞 Minecraft 服务线程。
- `StoneAuthority.java`：字典仅记录场景归属、观察位置和已发送状态，每次快照、请求或扫描都读真实后端。生产后端使用 `ServerLevel.getBlockState`、`setBlock`，只支持石头/空气；测试后端才是内存替身。
- 自带数据资源维度 `bannerlord_bridge:bridge`，使用空层 flat generator 和 void biome，不使用普通地形作为建造区。实际维度加载、石头状态命令检查及进入维度目视验证已通过，下方保留证据。
- 必须同时满足 JVM 参数 `-Dbannerlord.bridge.enabled=true` 与世界根目录授权文件 `bannerlord-bridge-test-world.txt`，文件内容为 `M3-STONE-TEST`，否则不启动桥接。默认关闭；标记文件不会自动创建。端口可由 `-Dbannerlord.bridge.port=25575` 指定。
- 首个成功放置的宿主整数坐标作为 anchor，映射到 MC `(0,80,0)`；后续 `(host.X-anchor.X, 80+host.Z-anchor.Z, host.Y-anchor.Y)`，即宿主 XY 水平轴映射到 MC XZ、宿主 Z 映射到 MC Y。BaseHeight 仍按 M2 用于宿主显示。
- 受控范围相对 anchor 为水平轴 `[-32,31]`、高度 `[-32,63]`，超出明确拒绝；观察位置最多 8192。删除/清空后保留观察位置和 anchor，场景结束/新会话清理后才重置。这是 M3 原型预算，不影响 M1 本地模式。
- 对已登记位置轮询，MC 外部删除或重新放置石头也产生权威增量；**未登记位置的外部新增方块不会自动导入**，不承诺任意 MC 世界同步。
- 快照/清理分帧，每次处理最多 32 个观察位置，软时间预算约 4 ms，单次引擎操作/区块生成可能超过预算。观察位置较多时扫描存在延迟，8192 个位置一轮可能约 13 秒，未作性能实测。
- 初次快照读超时扩为 30 秒，仍只发生在宿主网络线程；普通帧读写超时保留。心跳由 Java 网络线程处理，不依赖游戏 tick，但世界请求及同步必须等 MC 服务 tick。
- 同会话断线保留实际 MC 方块，重连从世界重建快照；新会话先清理旧归属。SceneEnd 即便对端随后关闭，仍分批处理已排队清理。正常停止 MC 服务在 SERVER_STOPPING 清理自有方块。
- 碰到非石头/空气的已登记状态，关闭当前连接，不销毁未知方块。异常退出可能留下维度中的石头；本阶段不做崩溃日志/归属持久化，不应直接复用污染区域或任意清除旧石头，建议使用新的专用测试世界。
- 当前无背包扣除、掉落、合成、红石、MC 玩家移动或伤害同步；仍沿用 Bannerlord 立方体外观，不涉及 MC 原版资源分发。

## 自动验证范围

构建脚本先通过实际 C# DataContractJsonSerializer 生成帧，再运行 Java `bridgeCheck`，最后让 C# 读取 Java 写出的帧，覆盖双向跨语言兼容性。生成帧位于 `artifacts/bridge-fixtures/`，不提交。

Java 检查覆盖异常帧、严格数值验证、去重、线程约束、坐标映射、源状态读写、已登记位置外部变化、非空重连、旧场景清理、分批清空、未知方块保护及世界授权标记。**方块后端使用测试替身，没有实例化 Minecraft 世界或启动游戏**，不能据这些检查宣称真实世界验收通过。M2 与原有宿主测试继续保留。

自动验证结果：37 项 Java 检查通过，C#→Java 两种帧及 Java→C# 增量帧兼容检查通过；34 项 M2 检查与原有诊断/几何测试通过。Mod 构建成功，宿主构建 0 警告/0 错误；源码审查、PowerShell 语法及 JAR 资源边界检查通过。这些自动检查不运行实际 Minecraft 世界；真实 Java 服务、维度和状态同步的独立实测结果见后文。

## 新环境部署与复测流程（已有实例无需重复初始化）

1. 用户确认后才安装独立 Fabric 测试启动配置、复制本项目 Mod、更新宿主 DLL；不覆盖普通游戏配置或现有存档。

3. 停止经身份核验的 M2 模拟服务，防止同端口冲突；MC 服务日志必须显示真实权威监听及维度。
4. 同时运行 MC 和 Bannerlord。集成服务器会因暂停/失焦停止 tick，须保持 MC 世界运行（可用 F3+P 关闭失焦暂停）；不要让 MC 停留在暂停菜单。也可后续评估独立服务端，不自动切换架构。
5. 在 Bannerlord 放置石头，并在 MC 中验证真实方块，例如在允许命令的测试世界使用
   `/execute in bannerlord_bridge:bridge if block 0 80 0 minecraft:stone run say bridge-stone-present`。
   宿主放置/删除应对应实际 MC 状态变化；对已登记位置执行 MC setblock 修改也应驱动宿主。
6. 验证断线非空恢复、离场/新场景清理及正常停止 MC；记录两端会话日志，不以模拟后端测试代替验收。
