# M2：模拟服务桥接

## 状态

已实现可选的本机桥接、独立 .NET 模拟权威服务及不依赖游戏的测试。
**M2 核心链路已完成本轮实机验收：正常建造、断线保护、服务重启后自动重连与快照恢复、恢复后操作及离场清理。** 未测项目仍单独保留，不据此承诺全部异常路径或规模性能。
不需要 Minecraft、Java、Mod 加载器或第三方 NuGet 包。

## 启用

1. 在仓库目录运行服务，保持终端打开：

   ```powershell
   dotnet run --project src/MockBridge/MockBridge.csproj -c Release -- 25575
   ```

2. 在 `%LOCALAPPDATA%\BannerlordBlocks\bridge-port.txt` 中写入一行 `25575`。
   也可用 PowerShell：

   ```powershell
   $config = Join-Path $env:LOCALAPPDATA 'BannerlordBlocks'
   New-Item $config -ItemType Directory -Force | Out-Null
   Set-Content (Join-Path $config 'bridge-port.txt') '25575'
   ```

3. 关闭游戏，按现有部署流程更新本项目模组，再进入新的单人自定义战斗。
   文件仅在场景初始化时读取；现有场景不会热切换。
4. 操作仍为 Ins 放置、PgUp 选择、Del 删除、PgDown 清空。
   Ctrl+PgUp 查看同步状态与序号。修改操作须等待上一条确认及镜像应用完成。

不存在配置文件时维持原有 M1 本地模式。配置无效或服务断线时禁止修改，
**不会偷偷回退到本地权威**。要回到 M1，请手动移除该配置文件，再进入新场景。
写入此配置、部署模组或启动游戏前必须取得用户确认。

## 实现边界

- TCP 固定绑定/连接 `127.0.0.1`；默认端口 25575，可选 1024–65535。
- `src/Bridge.Protocol/` 是共享源码，直接编译入宿主 DLL 和模拟服务，避免额外部署依赖。
- 协议 v1：四字节大端长度前缀 + UTF-8 JSON；每帧最多 1 MiB。
  类型包括 Hello、SceneBegin/End、SnapshotRequest/Snapshot、PlaceBlockRequest、
  BreakBlockRequest、ClearRequest、BlockDelta、Result、Heartbeat。
- 每场使用独立 GUID 会话及场景名。服务只支持一个宿主连接、一个场景；
  新会话替换旧状态，不支持并发多人或持久化。正常离场后台发送 SceneEnd；
  断线时保留旧状态以便同会话重连。若 SceneEnd 未送达，新场景仍通过新会话隔离。
- 方块状态由服务权威维护；宿主检查地面、边界、重复占用及角色空间后发送请求，
  收到权威消息才创建/删除实体。恢复快照不重新按玩家占用拒绝已有方块。
  请求到确认期间角色仍可能移动；本阶段没有预占位或两阶段提交，不承诺消除该时序窗口。
- v1 整数坐标对应宿主 X/Y 水平轴、Z 高度层；中心为
  `(X + 0.5, Y + 0.5, baseHeight + Z + 0.5)`，比例一米。
  首次放置确定场景高度基准，清空保留基准；服务重启空快照可重置。
  真实 MC 接入时须显式映射到 MC 的 X/Z 水平轴、Y 高度轴。
- 序号重复被忽略；缺号触发快照恢复；不同会话消息被拒绝。
  请求结果按 ID 缓存最近 1024 条。客户端不会自动重放断线时结果未知的请求，
  而是读取快照确认最终状态。连接失败约一秒后重试；心跳一秒，响应超时五秒。
  M3 后续复用客户端时，将初始快照网络读取超时扩展为 30 秒以容纳 MC 分帧快照；普通帧仍为原有超时，游戏主线程不等待网络。
- 网络线程仅处理协议队列；主线程每帧至多读取 16 条事件，
  至多进行 32 项实体工作，约 4 ms 后停止（单次引擎调用可能超过预算）。
  快照重建分帧进行，同步期间禁止修改；短时视觉重建不等于状态丢失。
- 出站队列 32、入站队列 128；超限使连接失效并恢复快照。
  M2 快照另设 **8192 块的传输/内存安全预算**，达到后明确拒绝放置。
  这仅作用于 M2，不恢复 M1 的 100 块限制，也不代表宿主能流畅渲染 8192 块。
- 本地协议无认证，不应连接不可信进程；不开放公网，不传执行命令或资源路径。
- 暂停期间允许同步既有状态，但不发送 PlayerState，也不模拟 tick 或暂停规则。
  背包、Minecraft 逻辑、持久化、战役与动态导航不在 M2 范围内。

用户按同步状态、放置/预览/碰撞/站立、选择删除、清空和退出再进入的测试指引反馈“实测没有问题”，并关闭游戏。按本轮反馈接受正常链路，不推断断线重连、暂停或大规模性能已通过。

### 服务断开与重启恢复（2026-10-05）

用户在场景中建造 3 块后授权停止本项目模拟服务，并反馈“断线表现正常”。诊断 session=`9b2541a6b078`，桥接 session=`12aede3a113047d498c35a11e53d7419`。日志记录断线与自动连接重试，期间采样仍为 blocks=3、errors=0；3 次 Ins 输入之后没有新的放置请求或创建记录。按用户反馈接受断线提示、禁止修改及游戏保持正常；删除/清空禁止的细项依赖用户本轮总体确认，没有独立协议日志。

结论：M2 核心正常链路、断线保护、服务重启后自动恢复、恢复后操作和退出清理满足本轮验收。无服务启动后再启动服务、保留服务进程只断连接时的非空快照实机恢复、人工注入迟到消息/队列超限和大规模批量更新仍未游戏内测试；相关协议与 loopback 自动检查不能代替这些实测。

观察到服务不可用期间每次连接失败都会提示并记日志，暂停后恢复可能集中显示多条；这不计为引擎异常，但断线提示节流尚未实现。
