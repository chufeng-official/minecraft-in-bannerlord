# 创造建造与战斗融合的 MVP 路线

更新：2026-10-05。第一版优先建立直观、可交互的创造建造体验，并验证其与霸主原生战斗的融合。**具体阶段范围与工作量仍是建议，不是时间承诺或已实现功能。** 已完成项目以验收文档为准。

| 阶段 | 核心结果 | 证据 |
|---|---|---|
| M0/M1 | 霸主加载、动态方块、碰撞、查询删除、预览与清理；跳过/未测细项保留限制 | [M0-M1.md](M0-M1.md) |
| M2 | 本机模拟权威、快照/增量、断线保护、重启恢复与场景隔离核心 | [M2.md](M2.md) |
| M3-A | 真实 MC 石头状态双向同步、宿主删除、两端清理、正常退出/重新进入恢复 | [M3.md](M3.md) |

现在是可验证的双引擎方块原型，不是具备完整玩法闭环的 MVP。背包仍未接入，因此整个 M3 尚未完成。默认保留 M1 本地模式，桥接需显式启用。

## 第一版目标：可重复体验的跨引擎玩法原型

核心体验是 **MC 风格建造 + 霸主原生四向战斗与骑乘 + 真实 MC 双向同步**，不是完整 MC 生存移植。

第一版以单人自定义战斗、创造式无限方块、一个经过实测的演示场景为范围。建造和战斗显式切换；不暂停战斗、不提供无敌，不改写霸主四向攻击。创造式操作不代表已经绑定或切换真实 MC 玩家的游戏模式，也不代表完成 M3 背包。

最小交付路径是 V0 → V1 → V2 → V4；V3 的人物外观为可选增强，验证失败不阻塞核心玩法交付。每阶段都应产出可独立实测的功能，逐步验证交互与视觉反馈。

## 分阶段路线

### V0：高风险资源与输入验证（先设门槛）

- 验证一块自制或授权明确的像素贴图方块能在霸主中显示，纹理清晰、尺寸与碰撞正确。
- 验证显式建造模式可以屏蔽原生攻击/格挡；切回战斗后四向攻击与骑乘恢复正常，暂停、失焦不产生误操作。
- 验证一个破坏粒子和一个定位音效的加载、触发及清理。
- 核对多类型方块需要扩展的协议、MC 状态映射和资源管线。

**通过标准：** 实机演示“有贴图的方块 → 放置/拆除 → 回到原生战斗”。资源工具或 API 不可用时先明确替代方案，不直接承诺完整模型移植。

### V1：一眼看出是 MC 的建造体验（最高优先级）

- 建造模式：中心准星、右键放置、左键瞬间破坏、合理距离与操作间隔；战斗模式保留原生操作。首版不支持骑乘建造。
- 固定创造快捷栏，首批完整方块建议：石头、圆石、橡木木板、橡木原木、泥土、草方块；玻璃在透明材质验证通过后加入。
- 方块选择、预览与实际放置一致。原木轴向、草方块多面贴图需显式实现；不支持的状态不得静默显示成另一种方块。
- 破坏碎屑、材质组破坏/放置音效；不做持续挖掘裂纹、掉落物或工具耐久。
- 保留本地模式与桥接模式的明确标识。桥接中由 MC 确认结果，失败有提示；重试/回传不重复播放效果，加载、重连和清空不逐块播放。
- 扩展多类型快照、增量和恢复，验证宿主与真实 MC 两边的类型/方向一致；无法支持的状态应明确拒绝或提示。

**验收场景：** 第一人称快速搭墙、切换方块、拆墙，并核对两端相同建造结果。本地交互与桥接同步分别验收，本地模式通过不代表同步通过。

### V2：建筑与原生战斗融合

- 制作一个紧凑的 MC 风格房屋、围墙或小型据点，使用手工预搭；只有重复搭建显著阻碍测试时才增加有确认的场景模板功能。
- 先用完整方块搭阶梯状屋顶、开放门洞；如观感确实不足，再按“台阶 → 楼梯 → 门”逐类增加几何、方向状态、碰撞和同步。
- 在已验证场景里测试“建墙 → 切回武器 → 四向战斗 → 原生骑马穿过 MC 风格建筑”。首版验收不依赖动态导航、AI 攻城或自动破墙。
- 从少量 Agent、小型建筑开始测，逐步增加方块与战斗规模，记录帧率、卡顿、碰撞和同步延迟，确定实际支持预算。

**验收场景：** 霸主士兵和骑兵与像素建筑共存；玩家现场放置、破坏方块并切换原生战斗，验证碰撞、输入隔离与玩法连贯性。

### V3：史蒂夫外观（可选增强，不阻塞核心交付）

1. 先验证第一人称方块手臂：镜头挂载、原生手臂隐藏、简单挥手、切模式恢复和穿模。
2. 再验证史蒂夫全身适配霸主骨骼，优先检查站立、行走、四向攻击与骑乘。外观 MC 化，动作仍用霸主系统。
3. 骨骼/动画适配成本过高时保留原生人物，或只启用已验证的建造手部；静态模型展示不计为角色适配完成。

首版坐骑保留原生马匹；MC 马外观和 MC 移动物理后置。第一人称手部方案同样需要验证，并非已确认容易实现。

### V4：稳定性与可复现验收（必做）

- 固定演示场景、方块/Agent 规模、启动顺序与桥接开关；提供可重复的准备、退出、清理步骤，不擅自修改世界或部署。
- 完整验收流程连续完成至少两次，检查模式切换、连点操作、同步、退出清理；检查暂停/失焦与断线时不会继续提交误操作。
- 按实测结果验证第一/第三人称视角的交互可用性，不扩展为通用相机系统。
- 调试信息可隐藏，但状态/错误仍可查。资源授权和公开文档所述功能与实际实现一致。
- 文档标明创造式操作、支持的方块、是否使用真实桥接，以及 AI/性能等限制；本地模式不计为真实 MC 联动。

**完成标准：** 能重复完成“MC 风格建造 → 破坏粒子/音效 → 原生战斗与骑乘 → 两端同步核验”，无阻断核心流程的异常。史蒂夫和特殊形状方块不作为最小交付门槛。

## 工作量与取舍

| 阶段 | 相对工作量 / 风险 | 优先级 |
|---|---|---|
| V0 资源、输入、效果验证 | 小范围但有引擎不确定性 | 立即 |
| V1 多方块、创造操作、效果与真实同步 | 中等，资源与状态映射是主要工作 | 必做 |
| V2 场景布置与战斗同框 | 完整方块方案可控；特殊形状明显增加工作 | 必做 |
| V3 手部与史蒂夫 | 中高风险，骨骼/动画可成为长周期 | 可选 |
| V4 稳定性与可复现流程 | 依赖规模实测，不能跳过 | 必做 |

旧路线的 **3–5 个迭代估计不再适用**。先完成 V0，再根据资源管线、输入拦截和同步扩展的实际结果估算。迭代包含实现、自动检查、用户实测及修复，不等同于固定天数。

## 首版明确后置

- 真实背包扣除/返还、生存、合成、工具耐久与掉落物（整个 M3 因背包未完成仍不标为完成）。
- MC 战斗规则、完整 MC 移动手感、MC 坐骑适配。
- TNT、红石、多人、战役/跨场景持久化、动态导航和 GPU 画面合成。
- 全部村庄方块、完整创造背包、通用建筑导入、大规模军团性能承诺。
- 面向公众的一键安装产品化；但开发者与测试者所需的可重复启动、停止与安全清理仍必做。

旧路线的真实背包权威、所有者绑定、物品结算和重试一致性要求保留为后续生存阶段的设计任务，不以创造模式替代其验收。

## 不能据现有测试外推的能力

正常停止 MC 后的空快照恢复已实测；服务进程保留只断 TCP 的非空恢复只有自动测试/设计依据，未完成游戏内实测。强制崩溃、残留恢复、8192 观察位置性能、大规模战斗、跨场景持久化仍不作承诺。M1 第 5 次计划复验及 50/100 块压力项曾由用户决定跳过，不视为通过。
