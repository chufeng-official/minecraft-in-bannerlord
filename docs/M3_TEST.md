# M3 测试实例：首次准备与已有实例复测

当前本机已完成 `.local/minecraft-instance` 独立实例、Fabric 启动版本 `fabric-loader-0.19.5-26.3`、两个 Mod JAR、`Bannerlord M3 Test` 启动配置及授权的 `M3-Test` 世界；M3-A 实测已通过，最后一轮后两款游戏均关闭。具体记录见 `M3.md`。首次准备时只新增版本和实例，没有覆盖普通启动配置或存档，世界由用户手动创建。

## 已有实例复测

1. 经本轮测试范围确认后，用已有 `Bannerlord M3 Test` 配置进入 `M3-Test`，不要重复运行初始化脚本或新建同名世界。
2. 保留独立游戏目录、启用 JVM 参数、Java 25 与世界授权标记；不要替换为普通存档。保持世界 tick 运行，不打开 MC 暂停菜单。
3. 先核验日志中的真实权威监听和 25575 进程归属，再启动 Bannerlord 自定义战斗。不得同时运行占用同端口的 M2 模拟服务。
4. 按本次约定步骤测试并记录两端状态；结束后正常退出战斗、保存退出 MC，检查清理。正常退出 MC 会清理桥接石头，本阶段不提供跨会话方块持久化。
5. 崩溃退出或陌生方块污染区域时先检查，不直接删除未知文件或拿主存档继续测试。

## 新实例首次准备（当前本机已完成）

以下是新的环境/实例初始化步骤，不是要求当前用户重做。运行准备脚本前须确认下载和安装范围；脚本拒绝覆盖已有版本或实例。

1. 打开 Minecraft Launcher，选择 **Minecraft: Java Edition → 安装配置 → 新建安装配置**。
2. 名称填 `Bannerlord M3 Test`；版本选择 `fabric-loader-0.19.5-26.3`。
   如果列表找不到，确认安装配置中的“已修改/Modded”筛选已启用，关闭并重新打开启动器。
3. **游戏目录**设为本项目 `.local/minecraft-instance` 的绝对路径。不要留空，不要选普通 `.minecraft`。
4. 展开“更多选项”，保留原有 JVM 参数，并在末尾追加：

   ```text
   -Dbannerlord.bridge.enabled=true
   ```

   Java 可执行文件保持自动选择（26.3 需要 Java 25）；不要指定系统 JDK 17。
5. 保存并启动这个配置。若启动失败，把报错发给开发者，不要切换到普通配置或修改其他 Mod。
6. 进入“单人游戏”，创建名为 **M3-Test** 的新世界，选择**创造模式**并**允许命令**。可使用超平坦世界加快准备；主世界不是桥接建造区。
7. 进入世界后停留几秒，**保存并退出世界，再关闭 Minecraft 和启动器**。
8. 告诉开发者“测试世界已创建，游戏已关闭”。

新建世界首次进入时没有授权标记，桥接应保持关闭；日志中出现授权标记缺失提示属于预期保护，不代表 Mod 加载失败。当前本机 `M3-Test` 后续已获授权，不适用这个初始状态。
开发者会检查该独立实例日志与世界目录，然后只为这个测试世界写入标记。
**本轮不要启动 Bannerlord，也不要使用普通存档测试。**

## 首次授权后的测试（等开发者确认）

授权后再次打开该专用世界，保持 MC 服务 tick 运行；失焦暂停已在新实例 options 中关闭。
开发者确认 `127.0.0.1:25575` 的监听属于真实 MC 服务之后，再启动 Bannerlord 自定义战斗。
后续步骤验证实际 MC 方块、宿主镜像、MC 端外部修改、断线与场景清理，不以截图或协议测试代替源状态验证。
